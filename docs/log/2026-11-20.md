## 결정
- **Step 12는 측정이지 교체가 아니다.** 판정 기준 ±0.03을 먼저 정하고 돌렸다. 결과: 파이프라인 숫자(hybrid+filter R@5, 124행)는 0.750 / 0.750 / 0.734 — 차이 없음. 기본 모델은 bge-m3 그대로, README는 손대지 않음(사용자 결정 대기).
- **eval_gate 기록 모드는 기준 모델(bge-m3) 행만 읽는다.** 게이트는 experiments.jsonl의 "method별 최신 행"을 읽는데, 오늘 실험으로 최신 vector 행이 KURE-v1이 됐다. 그대로 두면 CI 게이트가 다른 모델의 숫자(170행 vector R@5 0.849 < 0.865)로 실패한다. `embed_model == DEFAULT_EMBED_MODEL` 조건 추가 + 테스트.
- **기준 컬렉션은 다시 만들지 않는다.** bge-m3 색인 시간은 임베딩만 쟀다(`eval_embed index --dry`). 비기본 모델의 `index`만 컬렉션을 쓰고, 기본 모델로 `index`를 부르면 거부한다.
- **기본 모델이 아니면 산출물 파일명에 slug를 붙인다**(`failures_vector_<slug>.md`, `filter_trace_…`). 기준 실패 덤프를 다른 모델 결과가 덮지 않게.
- **negative cosine은 "벡터 후보 1위의 cosine"으로 통일**(rag.eval `negative.top1_cosine_mean/max`). hybrid+filter의 top1 점수는 RRF 값이라 안전선 판단에 쓸 수 없다 — graph가 보는 값과 같은 정의.
- 실패 집합 비교의 "틀림"은 R@5 0(기존 failures 파일 정의). 예시 원문은 임베딩만 바뀌는 vector method에서 뽑고, 건수는 두 method·R@1/R@5 모두 기록.
