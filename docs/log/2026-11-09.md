## 실험 — two_stage band 3차: train 점수 분위수 (lo = 음성 99분위, hi = 양성 1분위), 모델 ft_no_confusable_e2
| | 값 |
|---|---|
| train 상위 5 쌍 | 1,090 (음성 598 · 양성 492) |
| lo = 음성 q99 | **0.9998** (q90 0.887, q95 0.998) |
| hi = 양성 q1 | **0.0207** (q5 0.757, q10 0.976) |
| 뒤집힘(hi < lo) | 예 → 애매 구간 없음, 위임 0/325 |
| 이 band로 로컬만 판정했을 때 val 오류 | 양성인데 no(≤ lo) 100/146 · 음성인데 yes(≥ hi) 51/179 |

- 왜 뒤집히나: 음성 상위(≥ 0.9) 58건 중 **55건이 confusable 쌍** — no_confusable 변형은 이웃 원인 쌍을 학습에서 뺐으므로 모델이 그것들을 양성처럼 1.0 근처로 올린다. 음성 분포의 꼬리가 1.0에 닿으니 "음성 99분위"는 곧 1.0이다. val도 같다(음성 ≥ 0.9 14건 중 confusable 10).
- 결론: 이 모델의 점수는 확률로 보정돼 있지 않다(양성 중앙값 0.995, 음성 중앙값 0.008, 그런데 이웃 원인은 1.0). 분위수든 precision이든 train 분포로 band를 잡을 수 없고, "애매함"을 재려면 (1) confusable을 라벨 0으로 넣고 보정(temperature/Platt)하거나 (2) 라벨을 API 판정 기준으로 바꿔야 한다. 11-06 1차(precision band, false no_match 0.404)·2차(lo = threshold, 위임 49%·득 없음)와 합쳐 **two_stage는 현 라벨로는 성립하지 않음**으로 닫는다. 40% 기준으로 보면 2차가 49%로 이미 초과였고 3차는 0%지만 band가 뒤집혀 의미가 없다.

## Step 11 Day 2 — 집계 도구 + tool calling, 11-09 오전~낮 (`scripts/build_aggregate_evalset.py`, `scripts/eval_tools.py`)
### 결정
- **도구는 1개, 호출은 1회.** aggregate_tickets(cause_id | equipment_type | equipment_id | alarm_code, since) 하나만 주고 generate가 필요하면 한 번 부른다(두 번째 tool_call은 무시 — 비용 상한). 집계 축은 티켓 필드에 있는 것만: "증상 묶음별 원인 분포" 같은 질문은 의도적으로 못 자르게 둔다.
- 컨텍스트에 **원인 ID**를 넣는다(`최종 원인: … (원인 ID C01)`). 모델이 도구 조건으로 쓸 수 있는 값이 컨텍스트에 보여야 한다 — 없으면 설비·알람으로만 자르고(C01+C02 16건), 질문의 단위(정답 원인 8건)와 어긋난다.
- 집계 결과의 recent_ticket_ids는 인용 인정(kept 밖이라도 DB 행). 인용 0건 → no_match 후검증은 그대로.
- llm.chat을 `complete(messages, tools=…)`로 쪼갬 — 재시도·429 분류·토큰 계측은 하나. chat은 껍데기.
- **GRAPH_TOOLS 기본 on.** 근거: 대조군 65행 오호출 0, multi_hop 숫자 정확도 0.233 → 0.567, 비용은 전체 +16% 토큰(multi_hop만 +30%).

- off의 any_hit가 0이 아닌 건 last_seen 때문 — 최근 티켓이 상위 5에 들어 인용되면 "최근" 판정이 맞는다. 건수·다운타임은 off에서 **0/95** — 상위 5건으로는 전체 숫자를 말할 수 없고, 프롬프트가 "상위 5건 기준"이라 말하게 해서 지어내지도 않는다.
- 호출 20건의 필터: 원인+설비(+알람) 12 · 설비+알람 4 · 설비만 2 · 알람+기간 2. 정답 원인으로 자른 건 12/20(0.6) — 나머지 8건은 질문이 알람·설비 단위라 그 단위로 자른 것. 충실도 0.85: 받은 숫자를 그대로 쓴다. 3건은 도구 숫자(16건·174분)는 맞는데 정답(원인 8건)과 단위가 달라 any_hit 실패 — "숫자 정확도"는 집계 축 선택까지 포함한 지표다.
- 미호출 multi_hop 10건: "03:42에 전압 상승·증착속도 저하·두께 편차가 동시에" "증상 묶음의 원인별 분포" "중앙 540nm/가장자리 480nm 차이" — 도구 스키마에 없는 축(시각·증상 조합·측정치). 모델은 상위 5건으로 답했다(적절한 포기). 스키마를 넓히면 호출은 늘지만 집계 결과가 질문과 어긋날 위험도 같이 는다.
- 오호출 0/65: 도구 설명에 "단순 유사 사례·조치 순서 질문에는 부르지 않는다"를 넣은 효과인지, gpt-5-mini가 원래 보수적인지는 분리 못 했다(ablation 없음).
- 지연: 도구를 부른 질의는 생성이 2회(도구 결정 + 결과 반영)라 multi_hop +5.8s. 안 부른 질의도 tools 스키마가 프롬프트에 붙어 +500 토큰.
