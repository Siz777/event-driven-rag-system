## 단계별 한 줄

- Step 0: `OutboundEvent.asked_at`로 스레드 안 질문의 지연을 정확히(664.9s 착시 해소). drain 타임아웃 실험에서 멱등 가드가 requeue된 메시지를 300초 동안 버리는 틈을 찾아 키 release로 닫음(통합 테스트 test_k).
- Step 1: Kiwi + bm25s. 사전은 카탈로그에서 "기본 Kiwi가 잘못 쪼개는 단어만" 자동 검출(188 → 80, docs/experiments/kiwi_dictionary.md). 코드 경계는 `\b`가 아니라 영숫자 lookaround(한글이 \w라 "PECVD-03에서"가 안 잡혔다). 코드 단독 질의 0/5 → 5/5, human 0.842 → 0.947, paraphrase_hard 0.6 → 0.4.
- Step 2: RRF 1:1 고정. R@1·MRR 최고, R@5 불변, paraphrase_hard 0.6 → 0.567(못 살림), 코드 단독은 BM25 단독보다 못함(3/5). RRF 점수는 "모른다"의 근거가 못 된다(neg max = pos max).
- Step 3: 사전 매칭 라우팅 — 코드가 보이면 alarm_code 필터 + BM25 순위만, 설비 타입이 보이면 payload 필터. 코드 단독 5/5, 타입 오탐 0/9, 170행 중 38에 적용. negative 분리에는 도움 안 됨(positive도 같이 내려감).
- Step 4: LangGraph retrieve → grade(cosine<0.50 + 티켓별 yes/no, yes≥2) → generate|no_answer. negative 0.968, positive 오판 0.014, 정답 유실 0, 지연 +4.7s. 배치 판정 변형은 전 지표 열세로 기각.

## 결론

- "용어를 안 쓰면 무너진다"(1주차)는 하이브리드로도 안 바뀐다: paraphrase_hard R@5 0.6 → 0.567. 어휘 매칭은 용어가 있을 때만 돕는다. 임베딩 한계로 두고 개선 대상에서 뺀다.
- 하이브리드의 값은 **1위 적중**이다: human R@1 0.632 → 0.789, MRR 0.724 → 0.842. 사람 질의는 짧고 용어를 그대로 써서 BM25가 가장 잘 맞고, 코드 단독 질의는 벡터가 0/5라 라우팅이 필요했다.
- "모른다"는 점수가 아니라 판정이 말한다: cosine 임계값은 negative 9할을 잡으려면 positive 1할을 버려야 했고, 티켓별 yes/no에 "5건 중 2건 이상"을 걸어 negative 0.968·positive 손실 0.014·정답 유실 0. 값은 질의당 LLM 호출 5.67회, 지연 +4.7초.
