# 합성 티켓 라벨 검증 정책 (2심 + 사람 판정)

티켓의 정답 라벨(cause_id)은 카탈로그에서 복사되므로 틀릴 수 없다. 검증하는 것은 **"증상·조치 기록만 보고 그 원인을 맞힐 수 있는가"** — 라벨이 아니라 티켓 본문의 품질이다. 맞힐 수 없는 티켓은 검색 평가에서 정답으로 쓸 수 없다.

## 2심 구조

| 단계 | 심판 | 대상 | 통과 기준 | 스크립트 |
|---|---|---|---|---|
| 1차 | Ollama qwen2.5:7b (로컬, JUDGE_*) | 전체 | 예측 = 정답 또는 confusable_with | `scripts/validate_tickets.py` |
| 2차 | gpt-5-mini (LLM_*, 생성 모델과 동일) | 1차 탈락분만 | 동일 | `scripts/rejudge_failed.py` |
| 3차 | 사람 | 양쪽 탈락분 | 아래 3기준 | 수동, `_human_override` 필드 |

- 1차를 로컬 7B로 두는 이유: 전체 320건을 생성 모델과 **다른** 모델이 채점해 "자기 글 자기 채점" 편향을 피한다. 비용 0.
- 2차를 두는 이유: 7B는 설비별로 특정 원인에 쏠린다(2026-10-27: PHOTO 탈락 중 C28로 15건, ETCH에서 C12로 9건). 7B 탈락 = 티켓 결함이 아닐 수 있어, 탈락분만 큰 모델로 재판정한다. 생성 모델과 같은 모델이지만 탈락분(전체의 28%)에만 쓰므로 편향 영향이 제한적이다.
- 양쪽 탈락은 티켓 결함·카탈로그 결함·심판 한계 중 무엇인지 모델이 구분 못 하므로 사람이 본다.

## 사람 판정 3기준

1. **유지(keep)**: 증상이 정답 원인과 모순되지 않고, 현장 티켓으로서 자연스러움. 심판이 틀린 것으로 보고 복원. `_human_override: "keep"`.
2. **제외(drop)**: 증상이 정답 원인이 아닌 다른 원인을 명확히 가리킴(생성 오류). `_human_override: "drop"`, clean에서 제외.
3. **카탈로그 신호**: 두 심판이 **같은 오답**을 고르면 티켓 문제가 아니라 두 원인이 증상 수준에서 구분되지 않는 것. 티켓은 유지하고 카탈로그 `confusable_with`에 쌍을 추가한다(의도된 난이도로 편입).

## 2026-10-27 결과

- 320건 → 1차 통과 230 (72%) → 2차 복원 72 → 302 (94%) → 사람 판정 18건: **유지 16, 제외 2** → clean **318/320 (99%)**
- 제외: INC-2026-0136 (C17), INC-2026-0303 (C38)
- 카탈로그 신호 → confusable 추가 1쌍: **C10 ↔ C11** (0085·0086 두 심판 모두 C10)
- 상세: `domains/manufacturing/data/validation_report.json` (judge1 / judge2 / judge_bias / final.human_review)

## 주의

- 2차 심판 모델 = 생성 모델. 생성 모델을 바꾸면 2차 심판도 같이 바뀌므로 통과율을 세대 간 직접 비교하지 말 것.
- confusable_with 추가는 평가를 쉽게 만든다(해당 쌍은 정답 처리). 추가 근거는 반드시 여기에 남긴다.
